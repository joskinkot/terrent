# Предложения по улучшению

## Архитектура

Проект — небольшой CLI-клиент для загрузки и стриминга одного торрента через WebTorrent.

- `bin/terrent.js` — точка входа.
- `src/args.js` — парсер аргументов и справка.
- `src/download.js` — загрузка, выбор файлов, HTTP-стриминг и завершение работы.
- `src/progress.js` — TTY и pipe-вывод.
- `src/format.js` — форматирование и glob-шаблоны.

## Сильные стороны

- Простая и понятная структура модулей.
- HTTP-сервер привязан к `127.0.0.1`, поэтому не доступен извне.
- Поддержка HTTP `Range` через сервер WebTorrent.
- Файлы сначала полностью deselect, затем select нужные — избегает проблем с общими кусками торрента.
- Уже скачанные данные переиспользуются при повторном запуске в той же папке.
- TTY-прогресс отделён от обычного вывода.
- Реализованы остановка по `SIGINT`/`SIGTERM` и принудительный повторный `Ctrl+C`.
- Основная логика и зависимости сведены к одному основному пакету — `webtorrent`.

## Недостатки и рекомендации

### 1. Добавить тесты

Сейчас нет тестового раннера и проверочных scripts: в `package.json` есть только `start`.

Добавить:

- unit-тесты форматирования и glob-шаблонов;
- тесты парсера аргументов;
- smoke-тест локального `.torrent` без сетевого взаимодействия;
- тест завершения через `--exit-when-done`;
- тесты обработки отсутствующих файлов при `--only`.

Рекомендуется использовать встроенный `node:test`, доступный в Node.js 22+.

### 2. Зафиксировать зависимости

Нет `package-lock.json`, поэтому установленная папка `node_modules` не фиксирует точную разрешённую версию зависимостей.

Рекомендуется сгенерировать lock-файл и использовать единый менеджер пакетов в документации и CI.

### 3. Добавить проверки runtime API WebTorrent

Основная логика в `src/download.js` использует динамические свойства WebTorrent, такие как `torrent.ready`, `torrent.files`, `torrent.downloadSpeed`, `torrent.numPeers` и `torrent.infoHash`, без явных проверок типов или состояния.

Добавить защищённые helper-функции для расчёта статистики и получения состояния загрузки.

### 4. Унифицировать обработку ошибок

В нескольких местах используются прямые вызовы `process.exit(1)`. Это может помешать закрытию сервера, таймеров и соединений.

Рекомендуется централизовать завершение в `shutdown(code)` и передавать туда информационные сообщения об ошибках, чтобы поведение оставалось одинаковым для:

- ошибки запуска сервера;
- ошибки добавления торрента;
- ошибки торрента;
- ошибки клиента;
- отсутствия файлов под `--only`.

### 5. Расширить тесты glob-фильтрации

Glob-реализация в `src/format.js` экранирует специальные символы и заменяет `*` и `?`, но требует тестов на Windows-пути, пустой шаблон, Unicode и шаблоны со служебными символами regex.

Рекомендуется вынести glob-фильтрацию в отдельную функцию и покрыть типовые сценарии.

### 6. Исключить рабочие артефакты из репозитория

Папки `node_modules/` и `tmp/` выглядят как локальные рабочие артефакты.

Рекомендуется добавить `.gitignore` с правилами для:

- `node_modules/`;
- `tmp/`;
- скачанных файлов;
- тестовых `.torrent`-файлов;
- временных `.part` и иных файлов загрузчика.

## Результаты первичной проверки

- Синтаксис исходных JS-модулей проходит проверку Node.js.
- `node bin/terrent.js --help` выводит справку.
- `node bin/terrent.js --version` возвращает `0.1.0`.
- Парсер корректно проверяет порт, неизвестные опции, множественный торрент и обязательность значения опций.
- Реальное скачивание из сети не запускалось.
